# Jxnu 课程与个人课表系统全栈改造设计

## 1. 改造目标

以根目录 `ReadMe.md` 和 `docs/api-documentation.md` 为接口契约，将旧版课程管理改造为满足第三范式的课程、开课、排课和选课系统，并完成 Vue 3 前端、Spring Boot 3 后端及 MySQL 8 数据库的配套实现。

本轮保留现有 `student` 表中的预存账号数据，不迁移旧课程和旧选课数据，不直接执行本机数据库变更。交付可审查、可重复执行的迁移脚本和演示数据脚本。

## 2. 数据库迁移设计

### 2.1 保留与替换范围

- 保留 `student` 表及其中的登录账号、密码、头像和个人资料。
- 新建 `administrative_class`，为现有学生分配默认行政班后，再为 `student.class_id` 添加非空约束和外键。
- 删除并重建旧 `student_course`，使其关联 `course_offering`，不再直接关联 `course`。
- 删除并重建旧 `course`，移除 `teacher_name` 和 `number`，使用 `course_code`、`course_type`、`credit` 和 `weekly_periods`。
- 新建 `teacher`、`semester`、`classroom`、`class_period`、`course_offering` 和 `course_schedule`。

### 2.2 脚本划分

- `sql/01-migrate-schema.sql`：保留学生账号，按外键依赖顺序替换旧教学表并创建新结构。
- `sql/02-seed-reference-data.sql`：插入行政班、教师、课程、学期、教室、节次、开课与排课演示数据。
- `sql/03-seed-enrollments.sql`：根据现有学生账号插入可重复执行的演示选课数据。

所有脚本使用 MySQL 8 语法，显式包含外键、唯一索引、`CHECK` 约束和必要触发器。脚本通过事务和临时关闭外键检查处理重建顺序，但不删除 `student` 账号记录。

### 2.3 数据完整性

- 服务层负责可读的中文业务错误和事务控制。
- 数据库负责外键、字段范围、唯一性及“同一学生同一课程只能选一个开课班”的最终兜底。
- 排课的教室、教师和行政班时间冲突由服务层使用重叠区间查询检查。
- 一个开课班全部排课时段的节数之和必须等于课程周课时。

## 3. Spring Boot 后端设计

### 3.1 分层

- Controller：解析路径、查询参数和请求体，调用服务并返回统一 `Result`。
- Service：处理事务、实体存在性、排课冲突、容量、重复选课和名单权限。
- Mapper：只声明数据访问方法，SQL 全部位于 `resources/mapper/*.xml`。
- Entity：映射数据库表。
- DTO：表达新增/修改请求和面向前端的响应，禁止返回密码等敏感字段。

### 3.2 模块

- 学生账户：登录、当前学生信息、头像、修改密码；当前学生 ID 均从 token 获取。
- 课程：动态查询、详情、新增、修改、删除引用检查。
- 教师：动态查询、详情、新增、修改、删除引用检查。
- 基础资料：学期、行政班、教室和节次只读查询。
- 开课排课：查询、详情、新增、修改、删除和学生名单。
- 学生选课：已选列表、选课、退课和个人课表。

### 3.3 身份与异常

- 保持现有 JWT 令牌与 Spring MVC `HandlerInterceptor` 登录拦截方案；登录接口不拦截，其他接口由拦截器校验 token。
- 使用请求上下文工具统一取得当前学生 ID，避免 Controller 重复解析 JWT。
- `BusinessException` 表达业务失败；全局异常处理器将其转换为 `Result.error(msg)`。
- 非预期异常记录日志并返回稳定错误文案，不向前端暴露堆栈或 SQL 信息。

### 3.4 项目配置

- 按项目现有约定，阿里云 OSS endpoint、AccessKey、Secret 和 bucket 继续保存在 `application.properties`。
- 保持使用 Lombok，并在 Controller、Service 等需要记录运行过程的类上使用 `@Slf4j` 输出控制台日志。
- 密码兼容现有明文数据，本轮不扩大范围引入密码哈希迁移。

## 4. Vue 3 前端设计

### 4.1 路由

- `/login` 标记为公开路由。
- 需要学生身份的路由增加 `meta.requiresAuth`。
- 全局前置守卫检查本地 token：未登录访问受保护页面时跳转 `/login`，已登录访问登录页时跳转学生课表。
- `/studenthome` 默认重定向 `/studenthome/schedule`。
- 未匹配路径重定向首页或登录页，避免空白页面。

### 4.2 请求层

- 请求拦截器安全解析本地登录信息并携带 `token`，移除调试日志。
- 响应拦截器兼容无 `response` 的网络错误；401 时清理登录状态并跳转登录页。
- 业务错误由页面显示后端 `msg`，网络错误使用统一提示。

### 4.3 API 模块

- `course.js`：课程动态查询和 REST CRUD。
- `teacher.js`：教师查询和 CRUD。
- `reference.js`：学期、行政班、教室和节次查询。
- `offering.js`：开课排课查询、维护和学生名单。
- `studentCourse.js`：选课、退课、已选列表和个人课表。
- `stu.js`：当前学生信息不再接受学生 ID。

### 4.4 页面

- `studenthome/schedule.vue`：七天十一节个人课表、跨行课程块、学期切换、学生摘要、课程明细和同学名单弹窗。
- `studenthome/timetable.vue`：开课安排筛选、选课和退课，直接显示后端业务错误。
- `studenthome/courseinfo.vue`：按课程号、名称和类型筛选的课程目录，不显示教师字段。
- `studenthome/index.vue`：从当前学生接口加载头像，不向接口传学生 ID。

页面均提供加载中、空数据和失败状态；课表在窄屏下保持最小宽度并横向滚动。

## 5. 数据流

1. 学生使用学号和密码登录，后端返回 token 及基本资料。
2. 前端保存登录信息，路由守卫允许进入学生页面。
3. 页面通过 `/api` 代理请求后端并携带 token。
4. 后端从 token 取得学生 ID，按请求查询或修改数据。
5. Service 在事务内完成业务检查和写入，Mapper XML 执行 SQL。
6. 后端统一返回 `{code, msg, data}`，页面更新状态或显示明确错误。

- 使用服务层单元测试验证排课时段长度、总课时、三类冲突、重复选课、容量和名单权限。

- 使用 MyBatis 集成测试或可控测试数据库验证动态查询和关联映射。
- 保留并补充学生登录、头像、修改密码行为测试。

### 6.2 前端

- 提取课表网格转换为纯函数并测试跨行、空单元格和多时间段课程。
- 验证路由守卫的未登录、已登录和 401 清理逻辑。
- 运行 `npm run build` 验证所有 Vue 文件及依赖。

### 6.3 验收

- `mvn test` 全部通过。
- `npm run build` 成功且无编译错误。
- SQL 脚本经过静态检查；只有在用户明确授权且本机数据库可用时才执行联调。
- 登录、课程查询、开课查询、选课、个人课表、查看同学和退课流程符合接口文档。

## 7. 非目标

- 不实现教师或管理员登录。
- 不提供学期、行政班、教室和节次的前端维护页面。
- 不迁移旧课程和旧选课记录。
- 不实现考试、成绩录入和复杂跨班合班教学。
- 不在本轮强制迁移现有账号密码存储方式。
